# Independent plan review (Gemini 4 Neon High, 2026-11-22)

## 1. MCP now or later?

**Later.** Deferring the MCP server is the right call today.

- **Zero real diagnostics have been run.** Building a hosted server, state store, auth layer, and UI before validating the interview and scoring logic on 2–3 real small businesses guarantees you will cement untested assumptions into backend infrastructure.
- **Audience mismatch.** The clients of `agenticworks.ca` (trades, clinics, stores, agencies) are not connecting custom Streamable HTTP MCP servers with tenant Bearer tokens in VS Code 1.147. They run in Claude.ai/ChatGPT or sit on a call with you.
- **Privacy and upkeep.** Everything needed for v1—interview, deterministic math, local CSV profiling, Mermaid output, and a client-owned JSON file for quarterly re-runs—runs locally with zero hosting cost, zero auth surface, and zero client PII leaving the owner's machine (a real advantage for Canadian clinics and service businesses).
- **Protocol churn.** FastMCP 4.2.0 shipped nine days ago (2026-11-13), `io.modelcontextprotocol/skills` (SEP-2640) is still experimental, and the stateless `2026-07-28` MCP spec is four months old with dual-era compatibility baggage. Waiting lets the ecosystem settle while you validate the business.

**Concrete triggers to build an MCP server:**

1. **Live read-only data probes (primary trigger):** At least **2 paying Managed Diagnostic or retainer clients** need automated/quarterly pulls from a live tool (e.g., Jobber, Shopify, QuickBooks, Zendesk) because manual CSV exports are blocking adoption or quarterly re-runs.
2. **No-local-execution distribution (secondary trigger):** Paying clients or a distribution partner need to run the diagnostic inside an MCP host that cannot execute local Python scripts or load local Skills.
3. **Real benchmark dataset (optional later trigger):** You have **10–15+ completed diagnostics in one vertical** and real anonymized percentile data worth keeping server-side.

*Do not* treat "audit state across sessions/devices" ([plan.md](file:///C:/Users/Kamran/AppData/Local/Claude-Data/claude_pzs8sxrjxfjjc/scratch-workspaces/5b52e6fc-3aa8-4745-ab35-f2782166b325/4be1e782-b7d2-47ab-b302-b4ed35305881/scratch-2026-11-22-a82ba4/ai-opportunity-diagnostic/docs/plan.md#L47)) as a trigger—syncing a 3 KB JSON file across devices is a shared-folder problem, not a server problem.

**Smallest server when a trigger hits:**
- `score_diagnostic(case_json)`: thin wrapper over [diagnose.py](file:///C:/Users/Kamran/AppData/Local/Claude-Data/claude_pzs8sxrjxfjjc/scratch-workspaces/5b52e6fc-3aa8-4745-ab35-f2782166b325/4be1e782-b7d2-47ab-b302-b4ed35305881/scratch-2026-11-22-a82ba4/ai-opportunity-diagnostic/scripts/diagnose.py) for hosts without local code execution (plus real percentile lookup only after trigger 3).
- `probe_<system>_summary(days=30)`: strictly read-only aggregate counts and null rates (never raw PII rows) for the specific SaaS tool the paying client actually uses.
- `SkillCatalogProvider` serving the existing `SKILL.md` + `references/` folder *only* if connecting hosts lack local Skill installs.
- **Exclude:** `ui://` workbench, weight sliders, dual-era elicitation forms, and server-side audit DBs (keep the JSON file owned by the client).

## 3. What did the blueprint get wrong?

1. **Broken unit economics (treating gross revenue as profit).**
   In [original-blueprint.md](file:///C:/Users/Kamran/AppData/Local/Claude-Data/claude_pzs8sxrjxfjjc/scratch-workspaces/5b52e6fc-3aa8-4745-ab35-f2782166b325/4be1e782-b7d2-47ab-b302-b4ed35305881/scratch-2026-11-22-a82ba4/ai-opportunity-diagnostic/docs/original-blueprint.md#L312-L335) and [L427](file:///C:/Users/Kamran/AppData/Local/Claude-Data/claude_pzs8sxrjxfjjc/scratch-workspaces/5b52e6fc-3aa8-4745-ab35-f2782166b325/4be1e782-b7d2-47ab-b302-b4ed35305881/scratch-2026-11-22-a82ba4/ai-opportunity-diagnostic/docs/original-blueprint.md#L427), `$14,200/mo` in missed after-hours bookings becomes `$170,400` in `verified_annual_opportunity_usd` with `payback_days: 14`. That counts 100% of gross bookings as profit (ignoring technician wages, parts, and overhead), assumes 100% recapture (while its own kill criterion on [L354](file:///C:/Users/Kamran/AppData/Local/Claude-Data/claude_pzs8sxrjxfjjc/scratch-workspaces/5b52e6fc-3aa8-4745-ab35-f2782166b325/4be1e782-b7d2-47ab-b302-b4ed35305881/scratch-2026-11-22-a82ba4/ai-opportunity-diagnostic/docs/original-blueprint.md#L354) sets a 25% booking-conversion floor), and omits build cost from payback. That is the exact AI-ROI inflation the blueprint claims to eliminate.

2. **Unsound scoring math with dead zones.**
   - **Classification dead zones** ([L410-L415](file:///C:/Users/Kamran/AppData/Local/Claude-Data/claude_pzs8sxrjxfjjc/scratch-workspaces/5b52e6fc-3aa8-4745-ab35-f2782166b325/4be1e782-b7d2-47ab-b302-b4ed35305881/scratch-2026-11-22-a82ba4/ai-opportunity-diagnostic/docs/original-blueprint.md#L410-L415)): A `FRONTLINE_CORROBORATED` (`M_conf = 0.85`) candidate with `S_adj = 3.80, I = 3.50, F = 3.80` matches **none** of `QUICK_WIN` (requires `VERIFIED_TRACE`), `STRATEGIC_BET` (requires `F < 3.50`), `EVIDENCE_FIRST` (requires `M_conf <= 0.65`), or `DEFER` (requires `S_adj < 3.40`). Similar dead zones exist for `3.40 <= S_adj < 3.70` with `F >= 3.50`, and for `S_adj >= 3.40` with `I < 3.50, F < 3.50`.
   - **Undefined delta band** ([L393-L395](file:///C:/Users/Kamran/AppData/Local/Claude-Data/claude_pzs8sxrjxfjjc/scratch-workspaces/5b52e6fc-3aa8-4745-ab35-f2782166b325/4be1e782-b7d2-47ab-b302-b4ed35305881/scratch-2026-11-22-a82ba4/ai-opportunity-diagnostic/docs/original-blueprint.md#L393-L395)): `FRONTLINE_CORROBORATED` requires `Δ_role <= 0.25` and `UNCORROBORATED_DELTA` triggers at `Δ_role > 0.40`; `0.25 < Δ_role <= 0.40` is unassigned.
   - **False precision & mismatched floors:** Thresholding LLM-chosen 1–5 ratings to two decimal places (`3.70`, `3.20`, `3.50`) masks guesswork as precision. Multiplying `r_cost` by `M_conf` inside `I` ([L408](file:///C:/Users/Kamran/AppData/Local/Claude-Data/claude_pzs8sxrjxfjjc/scratch-workspaces/5b52e6fc-3aa8-4745-ab35-f2782166b325/4be1e782-b7d2-47ab-b302-b4ed35305881/scratch-2026-11-22-a82ba4/ai-opportunity-diagnostic/docs/original-blueprint.md#L408)) penalizes API efficiency for interview uncertainty while leaving unverified `r_data` unpenalized in `F`. And the `$10,000 USD` minimum gross-drag floor ([L371](file:///C:/Users/Kamran/AppData/Local/Claude-Data/claude_pzs8sxrjxfjjc/scratch-workspaces/5b52e6fc-3aa8-4745-ab35-f2782166b325/4be1e782-b7d2-47ab-b302-b4ed35305881/scratch-2026-11-22-a82ba4/ai-opportunity-diagnostic/docs/original-blueprint.md#L371)) is calibrated for mid-market consulting, not a 4-person clinic or trade shop where a $1,200 setup saving $7,500/yr is a clear win.

3. **Self-defeating architecture and privacy regression.**
   - V1 starts with "Skill-first, MCP-optional" and zero data egress; V2 contradicts both by centering the product on a hosted FastMCP 4.2 + React `ui://` + SQLite/Postgres + Bearer-auth stack and shipping raw `csv_text` over HTTP to `profile_evidence_csv` ([L222-L230](file:///C:/Users/Kamran/AppData/Local/Claude-Data/claude_pzs8sxrjxfjjc/scratch-workspaces/5b52e6fc-3aa8-4745-ab35-f2782166b325/4be1e782-b7d2-47ab-b302-b4ed35305881/scratch-2026-11-22-a82ba4/ai-opportunity-diagnostic/docs/original-blueprint.md#L222-L230)), introducing client data-egress liability for something a local script does safely.
   - Interactive rubric weight sliders ([L291](file:///C:/Users/Kamran/AppData/Local/Claude-Data/claude_pzs8sxrjxfjjc/scratch-workspaces/5b52e6fc-3aa8-4745-ab35-f2782166b325/4be1e782-b7d2-47ab-b302-b4ed35305881/scratch-2026-11-22-a82ba4/ai-opportunity-diagnostic/docs/original-blueprint.md#L291)) actively defeat the methodology by inviting stakeholders to drag weights until their preferred AI project turns green.
   - Protecting `benchmarks.json` server-side as an "IP moat" before completing a single diagnostic is protecting made-up numbers.
   - Requiring the Mermaid MCP connector (`chatgpt.mermaid.ai/anthropic/mcp`) adds a third-party account + OAuth setup step to render diagrams that Markdown/Claude already render natively.

4. **Calendar-driven sequencing before customer validation.**
   Building a remote MCP server, React workbench, vertical packs, and dual Lite/Pro release packaging in Weeks 2–4 *before* running the diagnostic on real operating businesses optimizes for engineering polish instead of learning whether the diagnostic actually converts small-business owners.
